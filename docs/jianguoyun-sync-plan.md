# 坚果云同步实施计划与 AI 交接文档

状态：待实现。本次只编写计划，未增加同步代码，未连接坚果云，未修改用户数据。

## 1. 给接手 AI 的任务

在现有 Windows 备忘录应用中增加基于坚果云 WebDAV 的多设备同步。
借鉴 Obsidian Sync 的本地优先、离线可用、后台同步和端到端加密体验，
但不接入、不复刻其私有协议，也不使用其品牌资源。

目标场景：同一用户在家中、公司两台电脑使用同一套备忘录，
两台电脑不必同时在线；先保存到本地，随后经坚果云交换变更。

本计划中的协议、表名和新增模块名是建议设计，不代表仓库已经实现。
接手后先核对最新代码，不要把本文当作现有实现说明。

### 1.1 默认决策

| 项目 | 决策 |
| --- | --- |
| 本地存储 | 保留 SQLite WAL，每台电脑各有自己的数据库 |
| 中转 | 应用直接调用坚果云 WebDAV，无需安装坚果云客户端 |
| 同步粒度 | 业务实体的版本与变更批次，不同步活动数据库文件 |
| 并发规则 | 基于修订关系识别冲突；保留所有冲突分支，不静默覆盖 |
| 远端布局 | 每个写入者独立追加日志，避免多个设备覆盖同一个共享索引 |
| 安全 | 正式发布默认端到端加密；凭据使用 Windows 安全存储 |
| 调度 | 单实例同步任务；启动检查、修改后防抖上传、周期拉取、手动同步 |
| 删除 | 软删除和彻底删除分开建模；保留防复活的删除元数据 |
| 第一版范围 | 单用户、一个活动同步库、至少两台 Windows 设备 |
| 非目标 | 实时多人协作、CRDT、手机端、网页端、自建账号服务器、附件同步 |

正式账号不能用于未加密原型。开发时可用本地假服务验证未加密逻辑；
端到端加密、冲突和迁移验收未通过，不得宣布同步功能可以正式使用。

### 1.2 不可破坏的约束

- 不改写用户真实数据库进行开发测试；使用临时目录和 `MEMO_APP_DATA_DIR`。
- 不回退或覆盖仓库内已有的美化、挂件生命周期等未提交改动。
- 未配置同步、离线、授权失效或云端故障时，现有本地功能仍然可用。
- 不把 `memo.db`、`memo.db-wal`、`memo.db-shm` 放入同步目录。
- 不依靠两台电脑的时钟判断谁的内容应被覆盖。
- 不把“彻底删除本机记录”等同于“历史密文已从坚果云及其备份物理擦除”。
- 禁止擅自清空远端目录、覆盖远端同步库、丢弃待同步队列或替换真实数据库。
- 公司电脑接入个人存储必须符合公司政策；加密不替代合规授权。

### 2.2 必须保留的业务语义

- 普通记录：完成时设置完成状态并移入回收站。
- 重复任务：完成时推进到下一个有效截止时间，通常不进回收站。
- 恢复：清除软删除状态，同时回到未完成状态。
- 删除分类：当前会把其中未删除的记录移入回收站，并删除分类及关联。
- 彻底删除、清空回收站：当前直接删除本地记录；同步后必须先留下删除修订。
- 提醒：`notified` 属于本机弹窗状态，不应阻止另一台电脑按自己的设置提醒。
- 主界面显示时挂件隐藏，最小化或关闭到托盘后出现；挂件收起和手动隐藏规则不变。

### 2.3 已发现、必须针对性处理的点

1. 本地记录和分类使用自增整数 ID，不能作为跨设备身份。
2. `updated_at` 是本地时间字符串，不能充当同步游标、全局版本或冲突判据。
3. `mark_notified()` 当前经 `_touch()` 更新 `updated_at`；
   必须把本机提醒变化与可同步业务变更分离，避免提醒引发同步回路。
4. `MainWindow.reload()` 会发出 `memos_changed`，搜索和刷新也会触发；
   该信号不是可靠的“业务已修改”事件，不能直接据此生成 outbox。
5. `add_memo_text()` 当前分开调用新增记录和设置分类；
   需要让一个用户操作的相关写入及同步修订原子提交。
6. 分类表 `name` 有唯一约束，`find_or_create_category()` 按名称匹配；
   两台设备独立新建同名分类时会有不同 UUID，必须明确处理而不是吞掉异常。
7. `purge()`、清空回收站以及删除分类的路径都要审计；不能只接管正文编辑。

## 3. 用户体验与同步范围

### 3.1 设置界面

提供：启用同步、服务地址、账号、应用密码、同步库选择或创建、
设备名称、测试连接、加密解锁、立即同步、暂停自动同步、
最近同步时间、待上传数量、冲突数量、脱敏错误信息。

默认地址：`https://dav.jianguoyun.com/dav/`。
默认根目录建议为 `memo-sync/`，具体同步库由 `vault_id` 隔离。

首次启用流程：

1. 输入服务地址、账号和坚果云第三方应用密码，测试连接。
2. 选择“创建同步库”或“连接已有同步库”，不能默认覆盖已有目录。
3. 创建时设置独立的加密密码并提示保存恢复材料；连接时输入已有库的密码。
4. 本地备份和迁移成功后，展示本机与远端数据概况、导入方式及重复风险。
5. 用户确认后执行初次合并，完成后展示数量与冲突，不只显示连接成功。

第二台设备需使用同一个 `vault_id` 和加密密钥体系。
连接信息可导出为不含账号密码、密钥或正文的配置文本；机密单独输入。

### 3.2 同步字段

| 实体 | 同步内容 |
| --- | --- |
| 备忘录 | UUID、正文、置顶、完成、创建/修改/软删除时间、截止时间、优先级、重复规则、提前提醒分钟数、分类 UUID 集合 |
| 分类 | UUID、规范名称、创建时间、删除修订 |
| 协议元数据 | 协议版本、修订 ID、父修订、操作 ID、写入者身份、删除类型 |

不跨设备同步：本地整数 ID、`notified`、分类折叠、窗口位置、
挂件位置/收起/隐藏、搜索条件、快捷键、凭据、同步游标和待发队列。

截止时间继续使用现有 Unix 秒值；不得重复进行时区偏移转换。
新增协议时间使用明确时区的 UTC，仅作展示和审计，不用于覆盖决策。
不在本功能中偷偷修改现有重复任务的时区和日历算法。

### 3.3 状态展示

区分：未配置、已暂停、同步中、已同步、等待重试、授权失效、
需要解锁、存在冲突、协议不兼容、数据校验失败。

“已同步”表示本轮已发布本机待发批次并处理本轮观察到的远端变更，
不承诺知道其他离线设备尚未上传的修改。
有未解决冲突时显示“同步完成，存在 N 个冲突”，不能用绿色状态掩盖冲突。

## 4. 技术方案：先验证能力，再冻结协议

### 4.1 阶段 0：坚果云能力验证

只使用明确获准的专用测试目录和虚构内容；不要让 AI 索取用户在聊天中粘贴密码。
凭据由用户在本机界面或安全输入流程配置。

必须验证并记录：

- HTTPS 证书验证、认证、超时、代理环境及 Windows 打包后的访问。
- `MKCOL`、`PROPFIND Depth: 1`、`PUT`、`GET` 的实际行为和状态码。
- XML 响应中的命名空间、路径编码、中文、空格、非 ASCII 名称、207 多状态错误。
- ETag、`If-None-Match`、`If-Match` 的实际支持情况，不能只依据通用 WebDAV 文档假定。
- 上传中断、响应丢失、相同路径重试、读取未完成对象时的表现。
- 750 项列表限制与实际分页方法；不假定标准 WebDAV 自带统一分页协议。
- 限流的实际状态码/响应和 `Retry-After`；不要为验证而主动压测到封禁。
- 当前账号的流量、配额、单文件大小限制与错误提示。

输出 `docs/jianguoyun-sync-protocol.md`，冻结 v1 格式、上限、状态机、
并发及失败恢复规则，并写明哪些性质由服务端保证、哪些由客户端补偿。
本阶段未通过，不要进入真实数据同步或对外承诺可靠性。

### 4.2 推荐远端布局

```text
memo-sync/
  <vault_id>/
    vault.json
    heads/
      <writer_id>.enc
    commits/
      <writer_id>/
        <sequence>.enc
```

- `vault_id` 为随机 UUID，创建新库不复用另一个库的路径。
- `vault.json` 是版本化、初始化后不可随意覆盖的加密配置；
  可含算法、KDF 参数和被密码保护的随机主密钥，不含明文主密钥。
- 每个 `writer_id` 只允许一个活动写入者；一个写入者顺序发布自己的日志。
- `<sequence>.enc` 为连续编号的加密批次，包含操作 ID、修订、完整实体快照及关联。
- `heads/<writer_id>.enc` 为加密且经过认证的已发布连续序号指针。
- 发现写入者只列 `heads/`，日志按已知序号直接读取，不扫描无限增长的目录。
- 第一版限制活动写入者数量在已实测的安全列举范围内；
  必须处理目录异常变大，不能把不完整列表当成“没有新设备”。
- 不维护由所有设备共同覆盖的 `all-notes.json` 或单一全局可变 manifest。
- v1 不自动清理远端日志、历史修订、删除标记；压缩和回收留到后续版本。

“只追加”也需要明确上传规则，不能将普通 PUT 当作天然的 create-only：
若服务支持可靠的条件创建则使用；否则在唯一写入者约束下，
重试前读取同路径对象并校验是否为同一批次，遇不同内容立即停止并报告。
不得把冲突路径上的不同对象直接覆盖。

指针是发现进度的入口，不是业务内容可信的充分条件。
先确认批次已成功存储，再发布指针；部分读取、错误密钥或认证失败都不能推进应用游标。
不依赖尚未验证的 MOVE、目录锁、原子重命名或跨文件事务能力。

### 4.3 写入者身份与恢复

`device_id` 为本机安装身份；`writer_id` 为该设备的日志写入世代。
身份不能仅保存在可复制的数据库中：普通重启应保留，克隆到另一台电脑应换新。

需要本机实例锁，禁止两个进程同时操作同一 outbox 和写入者日志。
数据库恢复、数据目录克隆或日志序号回退时，创建新的 writer 世代；
不得复用旧序号覆盖云端历史。发现远端指针回退或同序号不同内容时报警，
不能自动把它当作首次同步重置。

同一实体的并发由修订关系判定，不由 writer 世代或序号大小判定。

### 4.4 本地数据结构

保留整数主键供现有 UI 使用，新增稳定 UUID 映射、唯一索引和版本化迁移。
建议新增下列表或等价结构：

| 结构 | 用途 |
| --- | --- |
| `sync_profile` | 同步库身份、非秘密配置、协议版本；凭据只存引用 |
| `sync_outbox` | 和业务事务一起提交的待发操作，包含稳定操作/修订 ID |
| `sync_batches` | 已封装批次的 writer、序号、精确密文字节、摘要与发布阶段 |
| `sync_inbox` | 已下载且持久化的批次，允许依赖暂缺时稍后应用 |
| `sync_revisions` | 实体快照、父修订、当前分支集合、删除元数据 |
| `sync_peer_state` | 每个 writer 的发现、下载、应用进度，不混为单一时间戳 |
| `sync_conflicts` | 未解决冲突及其分支引用，不按每次下载重复创建 |

必须满足：

1. 业务写入和 outbox 同事务；一旦本地操作成功，就不能漏记其同步变更。
2. 批次分配、序列化、加密并持久化后才发请求；重试复用同一批字节。
3. 远端落库、去重标记、修订关系和应用进度同事务提交。
4. 接收远端更新不再生成新的本地用户操作，防止无限回传。
5. `operation_id`、`revision_id` 和批次唯一约束保证重复投递无副作用。
6. 修订的父节点缺失时持久化等待/补拉，不能按到达顺序强行覆盖。
7. 批次内多实体变化原子应用，例如删除分类连同记录软删除和关联变化。

### 4.5 同步循环与崩溃恢复

```text
读取当前 profile 与安全存储中的凭据
  -> 检查协议与加密配置
  -> 发现远端 heads，按序下载并持久化未知批次
  -> 按修订依赖应用可应用批次，保留本地并发分支
  -> 从 outbox 封装、持久化尚未发送的批次
  -> 顺序上传；验证成功后发布本 writer 的 head
  -> 持久化发布状态，通知 UI 刷新
```

- 网络请求前后都不长时间持有 SQLite 写事务；各线程使用自己的连接。
- 网络执行使用单个后台 worker 或等价异步方案；GUI 通过信号接收结果。
- GUI 与 worker 的数据库写入需明确串行化/短事务策略和 bounded busy 重试。
- UI 编辑中的文本不因远端刷新丢失；必要时保留编辑缓冲并提示冲突。
- 上传成功但应答丢失：同路径校验并重试，不新增一个不同的操作。
- 批次上传成功但 head 未发布：重启后继续发布，不能永久漏掉该批次。
- 下载后、应用前崩溃：从 inbox 继续；应用中崩溃由事务回滚。
- head 声称有某批次但 GET 暂时失败：保留缺口重试，不能跳过序号宣布完成。
- 依赖缺失、损坏或未知协议：显示需要处理，不把它伪装成空同步库。

## 5. 并发、删除与业务冲突

每个实体修订带 `revision_id`、`parent_revision_ids` 和完整同步字段。
顺序修改引用已知父修订；解决冲突的新修订引用所有已处理分支。

| 情形 | 处理 |
| --- | --- |
| 新修订是已有修订后代 | 采用后代；旧操作晚到不得倒退状态 |
| 两个修订互不为祖先 | 保留并发分支，进入冲突中心 |
| 重复投递相同修订 | 去重，无新增记录、无重复完成、无重复冲突 |
| 删除与编辑并发 | 不静默删掉编辑内容；显示删除/编辑冲突 |
| 顺序删除后旧设备上线 | 旧祖先不能使记录复活 |
| 明确恢复 | 发布引用当前已知删除分支的恢复修订 |
| 两端完成同一周期任务 | 同步已计算的结果快照，不在接收端再次调用 `toggle_done()` 推进 |
| 分类关联并发变化 | 视为记录修订的一部分，第一版不自行猜测集合合并意图 |

冲突分支以稳定 ID 保存；同一组分支在两台电脑重复拉取、重启、换顺序接收后不重复膨胀。
冲突展示和主列表投影应有确定性，不能按“先收到谁”随机决定。
解决界面至少提供保留本机、保留另一版本、编辑合并、另存一份；
选择后发布新的解决修订。若此时又到达未知分支，继续保留新冲突。

### 5.1 同名分类

不能按名称把不同 UUID 的分类和内容静默混在一起。
v1 默认保留不同分类身份，并采用确定性的可区分显示名/本地投影名，
例如附加来源或 UUID 短码；保留规范名称供将来显式合并。

阶段 0 必须决定如何兼容 `categories.name UNIQUE` 与快捷记录的按名匹配：
可以调整本地表约束并在 UI 消歧，或建立稳定的唯一投影名映射。
方案写入协议/迁移说明，禁止只捕获 UNIQUE 异常后丢弃远端分类。
快捷记录遇到歧义必须可选择或清楚显示落入哪个分类。

### 5.2 彻底删除的边界

彻底删除当前记录前，必须原子留下 purge 修订和防复活信息。
对“清空回收站”逐条保留身份与删除修订，不能只发一条无对象范围的全局指令。
与并发编辑冲突时，恢复材料在解决前不能丢弃。

v1 日志与历史密文仍可能保留旧正文；坚果云自身还可能保留历史或备份。
界面、帮助和确认文案必须如实说明“删除当前记录”与“擦除历史数据”的差别。
安全历史回收、密钥轮换和物理擦除不在 v1 内；如用户要求该保证，另行设计并确认，
不可擅自通过清空远端目录满足。

## 6. 加密、凭据与输入安全

- 使用成熟加密库，不自己实现算法。
- 建议随机生成库主密钥，使用 AES-GCM 等 AEAD 加密业务批次和 heads。
- 加密密码经 scrypt 或 Argon2id 派生密钥，保护库主密钥；参数、salt 和格式版本写入配置。
- 实际算法、参数、随机 nonce 策略、编码及大小上限必须在协议文档固定并交叉测试。
- 认证数据绑定 `vault_id`、协议版本、writer 与序号，防止不同上下文密文被误用。
- 认证失败不落库、不覆盖；错误密码、篡改密文和截断文件要有明确错误。
- 明文配置仅保留必要元信息；正文、分类名、完整实体身份等放入加密载荷。
- 不承诺隐藏流量、文件大小、目录结构、设备活动等所有元数据。
- HTTPS 始终校验证书；禁止 `verify=False`，认证重定向不得泄露到其他主机。
- 应用密码和解锁密钥存 Windows Credential Manager/DPAPI 或经过验证的等价方案；
  QSettings、JSON 配置、日志与导出诊断不能包含秘密。
- 安全存储不可用时拒绝明文持久化，可提供明确的仅本次会话输入。
- 远端视为不可信输入：校验 JSON schema、版本、类型、UUID、大小、依赖图和引用。
- 限制 KDF 参数、XML/JSON 响应体和批次大小，避免恶意文件造成资源耗尽。
- SQL 参数化；所有远端路径限制在所选 vault，拒绝路径穿越和越界 href。
- 连接测试只操作专用探针对象，不能遍历或读取账号下无关私人文件。
- 更换加密密码不应改变实体身份；完整轮换与恢复流程先设计，不能临时覆盖配置。
- 端到端加密不保护已解锁电脑上的本地明文 SQLite，也不保证抵抗云端删除/回滚攻击。

## 7. 调度、请求预算与错误恢复

初始建议：本地修改后约 5 秒防抖上传，远端约 120 秒轮询；
启动/恢复联网触发检查，手动同步可立即触发，但仍服从限流与单任务约束。
持续输入应有最迟发送窗口，避免防抖永远不触发。

坚果云官方目前说明免费用户每 30 分钟最多 600 次请求，付费用户最多 1500 次；
额度和限额可能调整，上线前复核。按账号总体用量保守设计，包含两端及其他应用。

- 一次同步不是一个请求：PROPFIND、GET、PUT、探测和重试均计入预算。
- 合并少量修改为有界批次，空闲不重复下载已知批次，不做每秒全量扫描。
- 设置保守的每设备预算及预留，达到预算后延迟，并显示下次重试时间。
- 初次同步或大量历史分批继续；不能因为一次拉不完就失败后从零开始。
- 网络错误和 5xx 指数退避加抖动；限流遵守服务响应，避免自动重试风暴。
- 401/403 区分失效凭据和权限问题，停止无意义的高频重试并引导处理。
- 超配额、协议错误、密码错误、暂时离线分别展示；暂停状态不自动恢复上传。
- 同步完成后远端数据变化才通知 UI 刷新；不因刷新重新触发上传。
- 退出时允许有限时间取消/结束任务，待发数据已持久化；不得无限阻塞退出。
- v1 不靠“退出时最后一次上传”保证正确性，也不承诺关闭进程后继续后台同步。

## 8. 迁移、初次合并与切换

1. 使用 SQLite Backup API 或等价一致性方案备份，并验证备份可打开；
   不在数据库仍运行时直接复制单个 `.db`。
2. 引入独立、版本化、幂等的 schema migration，失败回滚；
   不把大量同步初始化散落在窗口构造中。
3. 为旧记录、分类和关联建立稳定身份与初始修订；迁移重跑不能产生第二套 UUID。
4. 无同步历史的两份独立数据库，不能按整数 ID 或相同正文推断为同一记录。
   默认保留双方数据；明确提示可能重复，后续由用户选择去重。
5. 若第二台是第一台的旧数据库副本但此前无全局身份，也不冒险自动判同。
   可提供“备份本机后，以远端库建立新的本地副本”的显式选项，不能默认覆盖。
6. 本地为空时拉取完整历史；远端为空时需明确创建；
   非空、格式不明的目录不能自动当作新库初始化。
7. 中断初次同步后恢复进度，不重复新增；首次同步完成前本机新增仍可靠排队。
8. 禁用同步只停止网络活动，保留本地数据和队列。
9. 更换账号、路径或 vault 需暂停旧任务并确认；
   队列、游标、密钥和日志按 vault 隔离，不能把旧库待发数据自动传入新库。
10. 升级后旧版本程序继续写库可能绕过 outbox；明确不支持并行降级写入，
    提供版本检查、备份恢复说明，不宣称可无损随意降级。

## 9. 建议模块边界

```text
src/memo_app/
  sync/
    protocol.py       # 格式、校验、协议版本；不依赖 GUI
    crypto.py         # 密钥、AEAD、配置封装
    credentials.py    # Windows 安全存储
    transport.py      # WebDAV、认证、超时、路径与响应校验
    repository.py     # outbox/inbox/修订/游标的事务访问
    engine.py         # 拉取、发布、依赖处理、幂等和重试状态机
    service.py        # Qt worker、调度、取消和信号
  sync_dialog.py      # 设置/首次接入；也可复用现有设置页
  sync_conflicts.py   # 冲突查看与解决 UI
tests/
  sync/               # 假服务、双客户端、故障注入及协议测试
docs/
  jianguoyun-sync-protocol.md
  jianguoyun-sync-user-guide.md
```

这些是职责边界，不要求机械地建立所有文件。业务修改进入同一可靠写入入口，
不要为了同步复制第二套 CRUD，也不要将网络、加密和 UI 堆进 `db.py`。
第一阶段选定 HTTP/加密/凭据库后写入依赖，避免混用两套网络栈。

## 10. 实施里程碑

每一阶段交付可验证的纵向结果，不以“文件已创建”作为完成标准。

| 阶段 | 工作 | 退出条件 |
| --- | --- | --- |
| M0 能力与协议 | 测试目录验证、协议/安全/同名分类决策、依赖选型 | 有实测记录，故障语义明确，未解决假设列出 |
| M1 数据可靠性 | 一致性备份、迁移、UUID、修订、原子 outbox、本机状态分离 | 原功能通过，迁移幂等，本地成功操作不漏队列 |
| M2 最小闭环 | 真实 WebDAV 适配、E2EE、安全存储、加密批次上传/下载 | A 新增到 B，B 修改回 A；真实远端无明文正文 |
| M3 离线与并发 | inbox、幂等、崩溃恢复、冲突、删除、分类、重复任务 | 双客户端与故障注入用例全部通过 |
| M4 用户入口 | 设置、首次接入、状态、手动/自动同步、冲突 UI、主界面刷新 | 用户无需命令行完成双设备接入，不阻塞本地操作 |
| M5 发布 | 两机实测、独立审查、原路径打包、使用/恢复说明 | 验收矩阵通过，剩余限制如实披露 |

如坚果云实测否定推荐布局的关键前提，先更新协议与受影响测试，再继续实现；
不能悄悄退回整库覆盖、最后修改时间覆盖或共享 manifest。

## 11. 验收矩阵

自动化以两个独立本地目录/进程模拟 A、B，使用可故障注入的 WebDAV 假服务。
真实服务验证只用专用测试库，须经用户配置并明确允许。

| 编号 | 场景 | 必须结果 |
| --- | --- | --- |
| T01 | 未启用同步、服务不可用 | 原有本地功能可用，不弹窗轰炸 |
| T02 | A 新增，A 关机，B 随后启动 | B 获得完整记录及分类，不要求同时在线 |
| T03 | A/B 分别离线新增 | 联网后并集，无整数 ID 碰撞 |
| T04 | 两端离线修改同一条 | 两份内容可见且可恢复，不静默覆盖 |
| T05 | 冲突在 A 解决后 B 拉取 | 收敛到解决修订，重试不再复制旧冲突 |
| T06 | 解决时第三个分支到达 | 新分支保留，再次提示冲突 |
| T07 | A 软删除，B 持有旧祖先 | 不复活；若 B 并发编辑则明确冲突 |
| T08 | 恢复、完成、彻底删除、清空 | 语义与当前业务一致，删除有元数据 |
| T09 | 两端完成同一周期任务 | 不因回放额外推进一个周期 |
| T10 | 分类创建/删除、归类及同名冲突 | 身份与关联完整；无 UNIQUE 错误吞数据 |
| T11 | 重复下载、应答丢失、重启重试 | 幂等，无重复记录、修订或副作用 |
| T12 | 业务提交前后分别崩溃 | 事务原子性成立，无业务成功但 outbox 丢失 |
| T13 | 上传后、发布 head 前崩溃 | 恢复后继续发布，无孤立未发现变更 |
| T14 | 下载/应用中崩溃、父修订晚到 | inbox 可恢复，缺口不跳过 |
| T15 | 两台时钟相差一天、接收顺序颠倒 | 不按墙钟覆盖，最终分支一致 |
| T16 | 错误密码、密文篡改/截断、未知协议 | 拒绝不可信数据，本地不被覆盖 |
| T17 | 旧数据库迁移中断/重复执行 | 可回滚或重入，UUID 稳定，备份可恢复 |
| T18 | 克隆目录、恢复旧备份、双进程 | 不复用日志序号覆盖云端；实例锁有效 |
| T19 | 超过 750 个日志对象、较大历史 | 不漏记录，不依赖无界目录列表；可分批恢复 |
| T20 | 限流、5xx、超时、配额不足 | 有界退避，队列保留，UI 不冻结 |
| T21 | 仅弹提醒、搜索或 reload | 不产生业务上传；另一台仍按本机规则提醒 |
| T22 | 用户编辑时远端更新 | 编辑缓冲不丢失，冲突可处理 |
| T23 | 切换账号/vault、禁用/重启同步 | 不跨库泄露，无暗中清空队列或重新启用 |
| T24 | 断网退出、取消任务 | 有界退出，未发布数据重启可续传 |
| T25 | 安全存储或 HTTPS 依赖缺失 | 明确错误，不降级为明文或跳过证书校验 |
| T26 | 正式打包后双机使用 | 无开发环境依赖，HTTPS/E2EE/凭据功能正常 |

还需覆盖恶意 href、超大文件、循环/缺失修订引用、同序号不同批次、
head 回退、空响应、错误 MIME/XML、取消中的配置切换，以及去重后的稳定收敛。
明确初版支持的历史规模和实测请求量，不能用少量记录测试宣称任意规模可用。

## 12. 审查、打包与交付

- 遵守用户要求：每批代码修改完成后，用全新的独立子 agent 审查本次改动；
  修复后再换新的 agent，最多三轮，仍有问题则披露而不是无限循环。
- 审查至少关注：丢失更新、漏记 outbox、幂等、删除复活、秘密泄露、
  密钥/nonce、远端输入、线程退出、迁移和账号切换。
- 新增 UI 延续既有风格，需实际查看桌面/紧凑窗口/150% 缩放截图；
  独立视觉评分需达到用户此前要求的 9/10，不以源码推测代替看图。
- 用户要求打包前退出正在运行的本应用，直接更新 `dist/memo`，
  不再创建独立运行目录；优先正常退出，仅处理路径确认属于本项目的进程。
- 复核 `build_exe.bat`、`memo.spec` 与 `prune_dist.py` 的一致性；
  不可因裁剪丢失网络、TLS、加密、凭据后端、Qt SVG 等必要组件。
- 发布前在隔离目录验证 EXE 启动和完整同步，不拿真实数据库做启动冒烟检查。
- 不在本任务中清理旧 dist 目录、云端历史或真实备份；删除另需明确确认。
- 不主动提交代码、推送仓库或使用真实账号执行有副作用的测试，除非得到相应授权。

最终交付物：

1. 源码、迁移、依赖和故障回归测试。
2. `docs/jianguoyun-sync-protocol.md`：冻结的格式、状态机、兼容性与安全边界。
3. `docs/jianguoyun-sync-user-guide.md`：双设备配置、应用密码、恢复材料、冲突及故障处理。
4. 测试与真实服务验证记录、独立审查结论、截图、未解决风险。
5. 通过隔离验证的 `dist/memo/memo.exe`，以及明确的备份/升级说明。
